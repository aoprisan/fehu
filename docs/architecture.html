Where an order goes

The fehu sample venue has no locks anywhere. Every piece of state — each symbol's simulator and book, the market that holds everybody's money, the stream, the rate limiter — belongs to exactly one tokio task, and anything that wants it sends that task a job. Pick a path below and watch a request travel it.

The one rule: calls go one way. The market calls the symbols; the symbols call nobody. With no cycle there is nothing to deadlock, and everything that moves money queues single-file on one mailbox.

    Why the money is single-file

    A buy is checked against shares outstanding minus what traders hold minus what is already bid for. That subtraction is only true if nothing moves a book between the count and the submit — so the count, the account check, the submit and the reservation are all one job on one actor.

    What runs in parallel

    The expensive part. An engine step posts to all four symbol actors before waiting on any of them, so the simulators advance at once; the market then joins them in listing order and settles each one's fills, expiries and triggered stops.

    What a client sees

    Every published message takes the next sequence number, so a reconnecting client can ask for what it missed with ?since= — and is told plainly when the gap is older than the replay buffer.
