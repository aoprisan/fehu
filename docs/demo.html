fehu · economy server · a working model

A server you can watch

Everything below is running. A miniature of fehu-economy — its actors, its command journal, its ledger, its books and its world — is executing in this page, one command at a time, and every number you see was produced by it rather than written down. Push it around with the buttons, then crash it and watch the journal put it back.

The one invariant: nothing changes the market except a Command. The engine tick is one. Your order is one. Replay is the same apply over the same commands — which is why a snapshot plus the entries after it reproduces the world exactly, and why the hash at the bottom of this page comes back identical.

      Why it is built this way

      No locks anywhere

      Every piece of state belongs to one task and is reached by sending it a closure. Calls go one way — the market calls the symbols; the symbols call nobody — so there is no cycle to deadlock and nothing to design around. Money queues single file on one mailbox; reads go straight to a symbol and wait on nothing.

      The tick is a command

      A step carries the simulated instant it advances to, so an order that filled against the price at 12:04:31 fills against it again on replay. That is the only reading of the clock in the whole apply path: a command may not read anything a replay cannot.

      Refusals leave nothing

      Every path validates fully before it mutates. A command that is refused is not journaled, so a retry of a refusal is just tried again — and the idempotency index means a retry of a success gets the first answer back rather than a second effect.

      The stream is not the record

      Server-sent events are best effort, for charts. The same facts are appended to the outbox inside the command that caused them, numbered and retained, so a game backend that was restarting can ask again from its cursor and get them.
