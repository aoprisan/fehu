What we have

foundation

The parts that were already load-bearing before the trading-layer push, and are exercised by the test suite on every commit.

Price process

  • Four layers — fundamental value, OU mean reversion on the log-spread, GARCH(1,1) variance, Merton jumps
  • Events with decay — a shipped feature or a scandal fades on its own schedule
  • Market hours and overnight gaps under an optional calendar
  • Coarse mode — ten years of daily bars, highs and lows drawn from the Brownian-bridge extremum
  • Bit-identical across native and WebAssembly: xoshiro256++, libm, no clocks

Exchange

  • Limit order book with FIFO queues, priority carried on seq rather than the order id
  • Synthetic makers quoting a ladder around the reference, on the tick grid and in whole lots
  • Synthetic takers printing the tick volume as flow
  • Square-root impact — a trader's sweep pushes the next tick, then the push fades
  • Market, limit, FOK, IOC, plus stops, GTD, day and iceberg

Web app

  • Users, accounts, traders — money in cents on a ledger with signed, consecutive entries
  • Share supply bounded: holdings plus resting bids ≤ shares outstanding
  • Sessions and halts that freeze the book without stopping the clock
  • Idempotent submission, an order log that never evicts a live order, amend as cancel-and-replace
  • Save and restore at format 4, validated market-wide before a snapshot is accepted

Client and ops

  • Framework-free TypeScript UI — chart, book, tape, ticket, account and event panels
  • SSE stream that resumes at its own sequence and reloads only on a real gap
  • Reconciliation endpoint under the market lock, game-master authenticated
  • Rate limits per API key, spent by writes and never by reads
  • Health metrics — counts, means and high-water marks per route and per engine step

What is left

3 workstreams

None of these is simply unwritten. Each is blocked on a decision that wants making deliberately rather than in passing — which is why they are described here rather than filed as tickets.

1  Splits, and buybacks that retire stock

§15.3 Needs a rounding decision

A split is easy to describe and a lot of work to do honestly. It has to rewrite, atomically: every position's quantity and average cost; every resting order's price and size and the reservation behind it; the simulator's price and fundamental, or the price mean-reverts straight back; and every bar in Candles, the coarse daily history and the tape — or the chart lies.

Three of those live inside the crate, and Simulator, Candles and OrderBook have no way to rescale anything.

Blockers

  1. Levels collide. Dividing prices can round two book levels into one, and the merged queue still has to come out ordered by seq — which is now the priority.
  2. Reservations stop matching. After dividing a resting buy's price and multiplying its size, the reservation no longer equals price × qty, and reconciliation checks exactly that. Restrict to integer n-for-1 splits, round the reservation down and release the remainder — probably right, but it is a decision, not a default.

Suggested order

Give the crate Simulator::rescale, Candles::rescale and OrderBook::rescale with their own tests first. Then wire POST /api/symbols/{s}/split on top — the web-app half is the easy half.

The buyback is blocked elsewhere

Retiring stock needs shares_outstanding to change, and that is SymbolInfo — build metadata the save file deliberately does not carry. Same question as workstream 2, and it should be answered once for both.

2  Listing and delisting at runtime

§15.3 Core representation change

save::Symbol is a &'static str and TICKERS is a build-time array of four — and both assumptions run through the whole web app. The ledger, fills, order records, positions and reservations are all keyed on an interned static ticker, and serde is told as much.

This is a refactor of a core representation rather than a feature, and it is the thing to do before a retiring buyback, not after.

Blockers

  • Replace the representation everywhere — webapp/src/save.rs and every symbol module, plus each keyed collection that assumes a static lifetime.
  • Teach the save file a symbol table. Today a file listing other symbols is refused outright (§14.14); that check has to become a lookup.
  • Answer what a delisting means for the positions in that symbol — and for the money they were worth.

3  Splitting the market lock per symbol

§15.4 Think twice

Mutex<Market> is not only a bottleneck — it is what currently makes three separate things correct. A game server with four symbols and one engine step a second is nowhere near needing this.

Correctness that would have to be re-established

  • Reconciliation sees one consistent market-wide snapshot.
  • Share supply — held plus resting bids ≤ outstanding — is checked and acted on with nothing moving in between.
  • Order ids are allocated above every book's counter under one lock, which is what fixed the cross-symbol collisions in b109624.

Splitting it per symbol, with accounts still shared, means writing down an ordering discipline for those three and a lock hierarchy that cannot deadlock. That is a design pass with a performance target attached, not a refactor to do speculatively.

Watch-outs

noticed along the way

Not blockers, and not bugs anyone has hit — but each is a place where the next person will otherwise be surprised.

Doctests

cargo test --no-default-features including doctests fails, and did before this work: the README example uses ? with Box<dyn Error>, and the error types only implement std::error::Error under the std feature. The just test recipe passes --tests, which skips doctests, so nothing is red in practice. Fixing it means rewriting the README example not to use ?.

Maker fees

A positive maker fee is refused on purpose. A taker's fee is checked with the order, in the same moment it fills; a maker's would have to be reserved on acceptance and released exactly across every partial fill and cancel, and the rounding in that is a piece of work of its own. A maker rebate is allowed — it only ever credits.

Stop history

The stop store holds untriggered stops only. A stop that fires lives on as its order record and its stop_triggered message, not as a stop with a terminal status. A history of triggers would be a small bounded log and a listing endpoint.

Replay buffer

The replay buffer is memory, not a log. A restart begins the sequence at 1 again, so every ?since= after one is a gap. Persisting the last sequence in the save file is easy; persisting the messages would not be.

Admin auth

The game-master endpoints are open unless FEHU_ADMIN_KEY is set — which keeps the bundled UI's event panel working out of the box, and means anyone can move the prices on a shared server until that variable is set.
